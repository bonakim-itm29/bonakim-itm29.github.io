설명

학기 내내 배운 도구가 한 줄로 이어진다. 외부환경 분석과 델파이로 미래 시장·제품·기술을 그리고, TRM으로 매칭한 뒤 SWOT·AHP로 무엇을 개발할지 정한다. 이번 강의는 마지막 두 칸, 즉 R&D 결과를 평가하고 사업화·기술활용으로 연결해 다음 기획에 피드백하는 단계를 다룬다.

기술 Push와 시장 Pull

기술 PUSH
  • 기초·응용연구, 제품개발
  • 요소기술·주변기술·생산기술
두 개의 관문
  • 기술: 성능·파급효과·표준화·신뢰성
  • 시장: 경제성·투자·규제·경영과제
시장 PULL
  • 사회수요·사회목표·라이프스타일
  • 소비자 가치관·건강욕구·개인수요

기술은 기술·시장 두 관문을 모두 통과해야 사업이 된다

설명

SRI·AT&T의 도식이다. 연구에서 나온 기술이 아무리 좋아도 성능·신뢰성 같은 기술의 관문과 경제성·규제 같은 시장의 관문을 넘지 못하면 수요와 만나지 못한다. 성과활용을 계획할 때는 개발 기술마다 두 관문 중 어디가 막혀 있는지 먼저 점검하는 것이 출발점이다.

R&D 관리의 세대 변화

1세대(~1960s)
  • 관리 대상: 기술, 예산은 간접비
  • 연구는 고립된 섬, 선형·피드백 없음
2세대(~1970s)
  • 관리 대상: 프로젝트, 비용분담
  • 사업과 연계, 매트릭스 조직
3세대(~1990s 중반)
  • 관리 대상: 기업 전체, 위험/보상 균형
  • 기술·사업 통합, 내부 피드백 루프

설명

R&D 관리는 연구소에 맡겨두는 1세대에서, 사업부와 과제 단위로 연결하는 2세대를 거쳐, 전사 전략과 포트폴리오로 통합하는 3세대로 진화했다. 슬라이드의 연쇄모형 그림처럼 시장발견·설계·생산·판매 각 단계가 연구·지식과 수시로 주고받는 구조가 3세대 관리의 전제다.

시장 중심 vs 기술 중심 기업

시장 중심 R&D
  • 니즈 파악→컨셉→필요기술 확보
  • 고객은 파트너·자산
  • 시장조사는 인사이트·의사결정 기초
  • 신속·유연, 실수에서 학습
기술 중심 R&D
  • 기술개발→컨셉→시장 파악
  • 고객은 상하 관계·비용
  • 시장조사는 결정된 사항 정당화
  • 관행·단기성과 중시, 실수 회피

설명

같은 R&D 조직이라도 출발점이 시장이냐 기술이냐에 따라 경쟁사 파악 수준, 시장조사의 용도, 조직 운영이 달라진다. 기술 중심 기업은 이미 정한 개발을 정당화하려고 시장조사를 쓰는 함정에 빠지기 쉽다. 과제 기획서를 쓸 때 고객 니즈가 앞에 오는지 스스로 확인해 보자.

  2. 2Ⅱ 연구관리

  3. 3Ⅲ 평가·개선

    중간·최종평가, 사업화, 가치평가, 보상

  4. 4피드백

    결과를 DB·자산화해 다음 기획에 반영

평가 시점별 목적

  1. 1사전(선정)평가

    계획단계: 과제 선정, 목표·예산 배분

  2. 2중간평가

    수행 중: 달성도·진도 점검, 수정·중단

  3. 3완료평가

    완료 직후: 성과 파악, 후속 방향 설정

  4. 4추적평가

    일정기간 후: 활용 상황·파급효과 측정

15-2 R&D 성과평가 체계11 / 72
설명

같은 과제라도 언제 평가하느냐에 따라 묻는 질문이 다르다. 사전평가는 할 가치가 있는지, 중간평가는 계속할지 수정·중단할지, 완료평가는 무엇을 얻었는지, 추적평가는 실제로 쓰였는지와 고용·파급효과를 본다. 추적평가를 빠뜨리면 논문·특허만 남고 활용 성과는 측정되지 않는다.

투입→성과 논리모형

  1. 11 투입

    인력·아이디어·장비·시설·자금·정보

  2. 22 연구개발

    연구·개발·시험·결과보고

  3. 33 산출

    특허·제품·공정·출판물·지식

  4. 44 사업시스템

    마케팅·사업계획·제조·엔지니어링

  5. 55 성과

    원가절감·매출증가·제품개선·투자감소

15-2 R&D 성과평가 체계12 / 72
설명

산출(Output)과 성과(Outcome)를 구분하는 것이 핵심이다. 특허 5건은 산출이고, 그 특허로 원가가 10% 줄었다면 성과다. 산출이 사업시스템(마케팅·제조)을 거쳐야 성과가 되므로, 연구소 평가만으로는 성과를 설명할 수 없고 사업부 지표와 연결해야 한다.

설명

슬라이드는 세 가지 피드백을 그린다. ⑥ 내부 피드백은 연구소 안에서 결과보고가 다음 연구로, ⑦ 산출평가 피드백은 특허·제품 평가가 투입 조정으로, ⑧ 성과평가 피드백은 매출·원가 같은 사업 성과가 다시 투입 결정으로 돌아간다. 고리가 길수록 늦지만 가장 중요한 신호를 준다.

설명

지표는 R&D 시스템의 세 칸(투입·변환·산출)마다 따로 둔다. 산출만 보면 왜 성과가 났는지 설명할 수 없고, 투입만 보면 돈을 쓴 것 자체가 성과처럼 보인다. 실무에서는 칸마다 2~3개 지표를 고르고, 정량(건수·금액)과 정성(전문가 평점)을 섞어 균형을 맞춘다.

설명

연구개발의 효율은 R&D 생산성과 사업적 투자효율의 곱이다. 예: R&D 10억으로 사업화 가능 기술 2건(0.2건/억), 사업화 투자 20억으로 매출 60억(3배)이라면, 생산성을 0.4로 올리거나 투자효율을 6배로 올려야 효율이 두 배가 된다. 병목이 연구소인지 사업부인지 가려준다(예시 수치).

성과지표 설계 점검

  1. 1사전·중간·완료·추적 평가 시점이 모두 정해져 있는가?
  2. 2투입·변환·산출 칸마다 지표가 하나 이상 있는가?
  3. 3산출(특허·논문)과 성과(매출·원가)를 구분했는가?
  4. 4성과 지표에 사업부 데이터가 연결되는가?
  5. 5평가 결과가 보상·예산·다음 기획에 반영되는가?

설명

지표표를 만든 뒤 이 질문으로 빈칸을 찾는다. 가장 흔한 실패는 산출 지표만 잔뜩 두고 추적평가가 없는 경우다. 또 평가가 보상이나 다음 해 예산에 아무 영향을 주지 않으면 연구자들은 평가를 형식으로 여기게 되므로 피드백 경로를 반드시 명시한다.

설명

네 기준은 같은 현금흐름표에서 나오지만 보는 각도가 다르다. NPV는 규모(얼마 남나), IRR은 수익률(몇 %로 굴러가나), B/C는 효율(1원 쓰면 몇 원 버나), WACC 비교는 자본비용을 넘는지를 본다. 사업성 보고서에는 네 값을 모두 제시하고 전제(할인율·기간)를 함께 적는다.

설명

a=pm, b=q−p, c=−q/m이다. 판별식이 0 이하이면 해가 없거나 하나여서 p·q·m을 구할 수 없다. 예: 회귀 결과 a=10, b=0.4, c=−0.0004라면 cm²+bm+a=0을 풀어 m≈1,024(양의 해), p=a/m≈0.0098, q=−c·m≈0.41이다(예시 수치). q가 p보다 크면 구전이 확산을 주도한다.
